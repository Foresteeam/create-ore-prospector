# 机械动力：探矿仪 1.1.2

为 Minecraft **1.21.1 / NeoForge 21.1.219 或更新的 21.1 版本**制作的独立附属模组，对接工作区提供的 **Create 6.0.10** 和 **Create Ore Excavation 1.6.8**。使用 Java 21。

把成品 `create-ore-prospector-1.21.1-1.1.2.jar` 放入实例的 `mods` 文件夹，保留原来的机械动力与矿石开掘。升级时移除旧版探矿仪 JAR，推荐客户端与服务器都更新到 1.1.2；网络协议与 1.1.0、1.1.1 一致，不能与 1.0.0 混用。单人游戏只需安装在本机实例。不要把 `-sources.jar` 放进 `mods`。

手持「机械探矿仪」右键打开地图，右键方块也能打开。无需电力、压缩空气或耐久。玩家的红色方向箭头固定在地图中心，地图上方为北。矿脉按区块显示，颜色参考粗矿或矿脉图标的主题色；移入鼠标可查看矿种、储量、区块坐标和方块坐标范围。白色小点表示无限矿脉，暗色横线表示枯竭矿脉。

创造物品栏提供独立的「机械动力：探矿仪」分页，图标和内容均为机械探矿仪。物品注册 ID 为 `create:ore_prospector`。NeoForge 的内部模组 ID 不能带冒号，因此内部 ID 使用 `create_ore_prospector`。旧物品 `mechanical_prospector:prospector` 保留隐藏的兼容注册，已有存档中的旧探矿仪仍可使用；新合成和创造栏均提供新物品。

- 默认扫描 **65×65** 区块；点击范围按钮依次切换 **17、33、65、129** 个区块的边长。
- 最大一次扫描 **16,641 个区块**，约 **2064×2064 格**。
- 在地图上滚动鼠标滚轮可缩放，玩家始终保持居中；缩放不需要重新扫描。
- 在图例里点击矿种可高亮它，再次点击或使用「清除矿种筛选」恢复全部。图例支持搜索和滚轮翻页。
- 再次开图优先分批显示本地缓存，只向服务端请求缺失区块。跨越区块时也会复用重叠范围的缓存。
- 「重新扫描」跳过当前范围的本地快照，请求服务端读取实际矿脉和剩余储量；未生成区块已有的预测结果继续复用。ESC 关闭界面。

1.1.1 修复 129×129 地图的主要渲染热点：地图底图缓存在动态纹理中，稳定时每帧只绘制一个地图四边形；数据、缩放、筛选和位置变化时才更新底图，最多每秒 10 次。红色箭头、鼠标高亮和信息框仍逐帧响应。区块查询使用原生 long 哈希表，避免 `Long.hashCode` 对 X/Z 打包坐标产生大量碰撞。本地缓存解析和接收结果按客户端预算分批加入 UI，每 tick 还设有约 2ms 的处理时间预算；不再一次性解析全图，也不再每个响应包重建图例。

首次运行自动生成两个独立配置文件，本次 NeoForge 21.1.219 验证的路径为：

| 文件 | 配置段和字段 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `config/create_ore_prospector-client.toml` | `[client] maxScanChunksPerSecond` | 2048 | 每秒最多解析并加入 UI 的区块记录，本地缓存和服务器返回的数据共用预算 |
| `config/create_ore_prospector-server.toml` | `[server] maxScanChunksPerSecond` | 2048 | 服务端每秒最多开始的区块查询，所有玩家共享，缓存命中也计入 |
| `config/create_ore_prospector-server.toml` | `[server] predictionThreads` | 0 | 预测 CPU 工作线程数；0 自动选择 1～8 个，尽量预留两个逻辑核心；1～32 手动指定，重启生效 |

允许范围为 1～65536，不使用 0 表示无限。客户端低配时可以从 512 或 1024 开始，服务器根据其他负载调整；数值越小，地图填充越慢。两端均按单调时钟限速，暂停或空闲不会积攒大量可一次释放的额度；打开新地图也不会重置共享预算。服务端还保留每 tick 约 4ms 的工作时间预算，因此高配置值是上限，不保证达到设定吞吐量。配置中的 CLIENT/SERVER 使用 NeoForge 对应配置类型；整合包若覆盖服务器配置路径，以实际生成或生效的文件为准。修改后重新启动对应客户端或服务器最稳妥。

```toml
# create_ore_prospector-client.toml
[client]
maxScanChunksPerSecond = 2048
```

```toml
# create_ore_prospector-server.toml
[server]
maxScanChunksPerSecond = 2048
predictionThreads = 0
```

1.1.2 将未缓存区块的矿脉预测改为多核后台流水线。服务端先捕获只读的种子、矿脉规则、允许生物群系集合及私有存档字段，再按批次交给专用线程池。每批最多 32 个区块，共用一次完成通知；线程数、队列和在途区块数均有上限，队列满后在后续 tick 重试。候选位置按生成区域在每个工作线程内复用，重叠配方共用一次区块生物群系采样，减少重复随机数和噪声计算。

原版固定、棋盘、多噪声及末地生物群系源可在后台计算；未知生物群系源、噪声函数或自定义矿脉回调按需回退到服务器线程。后台不会调用世界区块缓存、访问可变配方/注册表或生成地形。实际已加载矿脉、网络响应与缓存提交由服务器线程处理；预测期间区块变为已加载时优先使用实际记录。数据包重载和正常停服会取消旧任务、关闭线程池，旧任务不会提交到新规则上下文。缓存格式与身份保持兼容，无需删除旧缓存。

多核加速的是 CPU 预测阶段，两端的 `maxScanChunksPerSecond` 继续独立生效。例如 16,641 条记录在客户端 2,048 条/秒的限制下，仅加入 UI 就至少约 8.1 秒；想更快填图，需要结合负载调高两端上限。普通稀疏配方的计算本身很短，线程调度可能超过并行节省的时间；较重的噪声或密集配方通常更能利用多核。`predictionThreads = 1` 仍在一个后台线程执行，适合希望减少 CPU 争用的服务器。

探测对象是 **Create Ore Excavation 定义的区块矿脉**，包含矿石和流体矿脉，也支持数据包添加的矿脉。储量单位是原附属的「开采次数」，每次产物数量由钻井配方决定。

打开工具时先向服务端取得当前服务器、世界、维度和规则版本对应的缓存标记，再读取本地记录。客户端只请求缺失区块；服务器优先读取共享缓存，未命中时才读取已生成区块的数据，或按 COE 的位置、种子、生物群系和优先级规则预测，并把结果写入缓存。多个玩家同时请求同一区块会共用一次解析，不重复预测。“无矿脉”区块也会缓存。

服务端的矿脉缓存位于 **服务器根目录/orechunk/**，缺少目录时自动创建；按世界 UUID、规则指纹、维度和 32×32 区块分区，使用原子替换写入压缩 JSON 文件。缓存会定期保存、完成扫描时保存，并在正常停服时保存，可在重启后复用。服务端身份文件是 `orechunk/server-id.txt`；世界 UUID 元数据保存在对应世界的 `data/mechanical_prospector_cache_identity.dat`。客户端缓存位于 **游戏实例根目录/orechunk-client/**，同样会保留到下次启动。缓存区分服务器、世界和维度，避免同坐标的数据混用。

本地和服务端缓存都是快照，普通开图优先复用快照以减少网络和计算。开采后需要最新余量时，点击「重新扫描」：服务端读取已加载或已保存的实际开采记录并更新缓存；如果区域仍未生成，则继续使用原预测，不重复生成矿脉信息。数据包重载、配方或相关配置变化后会使用新的规则指纹（配置变更后重启服务器生效）。

数据来源会显示在悬停信息中，包括本地缓存、服务端缓存、实时数据、存档数据和预勘测。未生成区域的有限矿脉显示「预估初始储量」；实际生成后可刷新确认。扫描不批量生成地形，也不消耗或重置原矿脉。

完整 Java 源码、资源、配方、纹理生成工具和测试均在本文件夹。`libs/` 保留了用户提供的两个原始依赖，只用于开发，不会打进成品 JAR。

安装 JDK 21 并设置 JAVA_HOME 后，在本目录运行：

```powershell
.\gradlew.bat build
```

输出位于 `build/libs/`，测试报告位于 `build/reports/tests/test/index.html`。当前共有 37 项测试：包括四工作线程同时运行、队列回压、逐项异常隔离、停机取消、三维度及存档预测一致性、规则与棋盘生物群系标签的快照隔离、未知生物群系回退、冷缓存重载，以及 1.1.1 的注册、配方、网络、缓存、储量、限速和地图像素回归测试。预测集成测试还记录 129×129 个区块在单工作线程/四工作线程下的计算耗时，分别使用测试框架的平坦主世界默认规则与密集下界噪声规则；这些数据不等同于游戏 FPS 或完整扫描耗时。

Windows 的中文路径可能使 Java 测试进程解析类路径失败。可以使用 ASCII 路径，或使用 Windows `subst` 为本目录临时分配空闲盘符后构建。结束后释放自己创建的盘符即可；此问题不影响成品在游戏里加载。

网络下载失败或缓慢时，可读取 Throne 当前系统代理设置，然后向 Gradle 传入对应代理参数，例如本次验证时的端口：

```powershell
.\gradlew.bat '-Dhttp.proxyHost=127.0.0.1' '-Dhttp.proxyPort=2080' '-Dhttps.proxyHost=127.0.0.1' '-Dhttps.proxyPort=2080' build
```

如果 NeoForge 主 Maven 域名解析异常，也支持参数 `-PneoForgeMirror=https://1755624453.rsc.cdn77.org`（该域名为本次核对的官方 Maven CDN 别名）。图标可在项目根目录运行 `java tools/GenerateTexture.java` 重新生成。
